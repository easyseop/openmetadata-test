# OpenMetadata 업그레이드 가이드 독립 검토 요청

첨부한 `docs/00-사용가이드/OM_TEMP_1.13.0_1.13.1_업그레이드_실행_가이드_미리보기.html`을
처음 보는 비개발자·부서 책임자의 관점과 Git/OpenMetadata 기술 검토자의
관점에서 각각 검토해 주세요.

## 이 문서가 설명해야 하는 상황

- 공통 기준 코드는 공식 OpenMetadata 1.13.0입니다.
- 공식 쪽은 1.13.1로 올라가면서 번역 JSON의 형식·항목 배치가 크게 바뀌고
  공식 번역 항목도 변경됐습니다.
- BANK-OM-001은 공식 1.13.0 구조를 기준으로 같은 JSON 객체에 행내 번역
  항목 9개를 추가한 변경입니다.
- 공식 1.13.1에 BANK-OM-001 변경을 기능 단위로 적용했을 때 번역 JSON
  18개에서 실제 Git 충돌이 발생했습니다.
- `ko-kr.json` 충돌 원문은 6,614행입니다. `HEAD` 쪽 충돌 내용은
  3~2,375행, BANK-OM 쪽 충돌 내용은 2,377~5,554행입니다. 1행과
  5,556~6,614행은 충돌 표시 밖에서 Git이 자동으로 맞췄습니다.
- 즉 화면의 좌우 한 줄을 비교하는 충돌도, 두 전체 파일이 통째로 충돌한
  것도 아닙니다. 한 파일 안의 매우 큰 두 충돌 블록입니다.
- JSON 항목 이름을 기준으로 의미를 다시 비교했을 때 공식 1.13.1과
  BANK-OM-001이 동시에 변경한 동일 항목은 0개였습니다.
- 해결은 공식 1.13.1 파일을 기준으로 유지하고 BANK-OM-001의 새 항목
  9개만 추가하는 방식으로 수행했습니다. 7개는 `label`, 2개는
  `message` 객체에 들어갑니다.
- 이번 후보 생성에서 `git cherry-pick`을 쓴 이유는 기능별 BANK-OM
  커밋을 하나씩 적용하여 어느 ID에서 충돌했는지 분리해 기록하기
  위해서입니다. 이것이 유일한 운영 병합 방식이라는 뜻은 아닙니다.

## 반드시 확인할 항목

1. 독자가 “공식 코드와 BANK 코드가 같은 한 줄에서 서로 다른 값을 가진다”고
   오해할 만한 도식·배치·문장이 남아 있는지 확인해 주세요.
2. 충돌 블록을 파일 전체라고 잘못 설명하거나, 충돌 밖에서 Git이 자동으로
   맞춘 영역을 누락한 부분이 있는지 확인해 주세요.
3. “들여쓰기만 달라서 충돌했다”는 식으로 원인을 지나치게 단순화하거나
   사실과 다르게 설명한 부분이 있는지 확인해 주세요.
4. 공통 기준 1.13.0 → 공식 1.13.1 변경 / BANK-OM-001 변경 →
   자동 병합 중단 → 담당자 해결 → 검사라는 인과관계가 끊기지 않는지
   확인해 주세요.
5. `HEAD`, commit SHA, cherry-pick, watch, Manifest, APPROVAL 등 용어가
   처음 등장할 때 그 문맥에서 이해할 만큼 설명되어 있는지 확인해 주세요.
6. 실제로 구현·실행·확인된 내용과 운영 전 추가 검증이 필요한 내용이
   시각적으로나 문장상 섞이지 않는지 확인해 주세요.
7. 같은 설명이 반복되거나, 앞 문장을 삭제한 뒤 질문·답변만 남아
   갑자기 등장하는 표현이 있는지 확인해 주세요.
8. 코드·표·도식의 글자 크기, 대비, 줄바꿈, 펼치기 구조가 읽기 쉬운지
   확인해 주세요.
9. 문서의 사실 주장 중 첨부 HTML만으로 근거를 확인하기 어려운 부분을
   별도로 표시해 주세요. 추측으로 사실을 보완하지 말아 주세요.

등록 전 중단

Manifest·Registry·Contract는 사용자와 함께 작성

release branch는 만들지 않습니다. 최초 기준환경은 업그레이드 검사 통과 결과가 아닙니다. 이후 1.13.2 업그레이드와 검사·승인을 통과한 코드에서 처음 만듭니다.

2. 복원에 사용한 입력

구분값뜻
공식 commitafcb2d2cd7e7…공식 1.13.1 릴리스 코드 위치
공식 treea8290d23b0fb…공식 1.13.1 전체 파일 상태 번호

commit은 이력의 위치, tree는 그 위치의 전체 파일 상태입니다. “실제 원본과 같은가”는 tree 번호와 전체 diff로 확인합니다.

4. 단계별 실행

4-1. 별도 작업 폴더 만들기

입력

출력
기존 작업과 분리된 복제본
git clone --filter=blob:none --no-checkout https://github.com/easyseop/OM_TEMP.git work/om-temp-real-1.13.1

4-2. 실제 원본 연결하기

입력
로컬 kb_openmetadata 복제본
출력
kb-source/main과 공식 태그
git remote add kb-source /path/to/review-kb-openmetadata
git fetch kb-source refs/remotes/origin/main:refs/remotes/kb-source/main refs/tags/1.13.1-release:refs/tags/1.13.1-release

4-3. 공식 스냅샷 기록하기

OM_TEMP의 기존 스냅샷 방식에 맞춰 공식 전체 이력 대신 공식 1.13.1 파일 상태와 원본 commit 정보를 기록합니다.

git commit-tree a8290d23b0fb7a4bdc860c2ff414d799f66417c5 \
  -p 2f4f3560e7a8437e2f4f7fcafd00d32ea2d91a50 \
  -m 'Import official OpenMetadata 1.13.1 source snapshot' \
  -m 'Upstream-Tag: 1.13.1-release' \
  -m 'Upstream-Commit: afcb2d2cd7e7c28f1d0ce60538c60a96f4eb9dc9' \
  -m 'Upstream-Tree: a8290d23b0fb7a4bdc860c2ff414d799f66417c5'

4-4. 실제 커스터마이징 기록하기

공식 스냅샷을 부모로 두고 실제 kb_openmetadata tree를 그대로 기록합니다. BANK-OM 기능별 등록은 아직 하지 않습니다.

git commit-tree 1df344b65844307fb4637f427778afa4d3b13bf7 \
  -p e6199070c35f717f7ced512bb7b435b9d46b33a3 \
  -m 'Restore actual kb_openmetadata 1.13.1 customization baseline' \
  -m 'Source-Snapshot: 2c2347043235aa2a4ecba4729774c770fcee5d67' \
  -m 'Source-Tree: 1df344b65844307fb4637f427778afa4d3b13bf7'

5. 무엇을 확인했고 결과가 무엇인가

확인 질문명령실제 결과

전체 파일 상태 번호가 같은가?git rev-parse …^{tree}1df344b65844…로 동일

6. 등록자료를 지금 만들지 않는 이유

113개 파일 차이를 기능 단위로 나누려면 “이 파일은 어떤 BANK-OM 기능에 속하는가”라는 업무 판단이 필요합니다. 이 판단을 자동으로 확정하면 잘못된 Manifest와 Contract가 생길 수 있습니다.

다음 산출물사용자와 함께 정할 내용
Manifest기능별 필수·허용·감시 경로
RegistryBANK-OM ID, 담당자, 상태, 기준 commit 이력
Contract기능이 정상이라고 볼 업무 동작과 필수 test
현재 상태: 검사 입력을 만들기 직전의 정확한 코드 기준환경만 완료됐습니다.

7. 다음 세션은 여기서 시작

  • 원격 두 브랜치와 commit을 재확인합니다.
  • 공식 대비 113개 변경 목록을 기능 단위로 분류합니다.
  • 기존 BANK-OM ID에 속하는 변경과 새 ID가 필요한 변경을 구분합니다.
  • Manifest → Registry → Contract 순서로 초안을 함께 검토합니다.
  • 사용자 승인 뒤에만 등록자료를 반영하고 검사를 실행합니다.

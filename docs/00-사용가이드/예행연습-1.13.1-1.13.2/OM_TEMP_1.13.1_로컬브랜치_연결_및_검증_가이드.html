3. 단계별 실행

3-1. 원격 branch 정보 갱신

수행 내용 — 원격 branch 위치를 로컬 Git 정보에 반영합니다. 코드 파일은 아직 변경하지 않습니다.

입력 — 인터넷 연결과 OM_TEMP 읽기 권한

git -C ~/om-work/om-temp-real-1.13.1 fetch origin

예상 결과 — 오류 없이 종료됩니다.

중단 조건 — 로그인 오류 또는 Repository not found

3-2. 원격 official commit 확인

수행 내용 — 로컬 official branch가 연결될 원격 commit을 확인합니다.

git -C ~/om-work/om-temp-real-1.13.1 rev-parse refs/remotes/origin/official/om-1.13.1

예상 결과 — e6199070c35f717f7ced512bb7b435b9d46b33a3

중단 조건 — 예상 commit과 불일치

3-3. 원격 custom commit 확인

수행 내용 — 로컬 custom branch가 연결될 원격 commit을 확인합니다.

git -C ~/om-work/om-temp-real-1.13.1 rev-parse refs/remotes/origin/custom/om-1.13.1

예상 결과 — 59dae915342eaa3bdca1f9571bfa2ba4533c9a6f

중단 조건 — 예상 commit과 불일치

3-4. 로컬 branch 중복 여부 확인

수행 내용 — 같은 이름의 로컬 branch가 이미 있는지 확인합니다.

git -C ~/om-work/om-temp-real-1.13.1 branch --list official/om-1.13.1
git -C ~/om-work/om-temp-real-1.13.1 branch --list custom/om-1.13.1

예상 결과 — 처음 실행하는 환경에서는 두 명령 모두 빈 출력입니다.

분기 조건 — branch가 표시되면 3-5·3-6을 건너뛰고 4장의 commit 검증을 수행합니다.

3-5. 로컬 official branch 연결

수행 내용 — 원격 official branch를 추적하는 같은 이름의 로컬 branch를 만듭니다. 현재 branch는 바뀌지 않습니다.

입력 — origin/official/om-1.13.1

git -C ~/om-work/om-temp-real-1.13.1 branch --track official/om-1.13.1 origin/official/om-1.13.1

산출물 — 로컬 official/om-1.13.1 branch. 4-2의 기준 commit 검증에 사용됩니다.

3-6. 로컬 custom branch 연결 및 코드 구성

수행 내용 — 원격 custom branch를 추적하는 로컬 branch를 만들고 전환합니다. 코드 파일이 작업 폴더에 구성됩니다.

입력 — origin/custom/om-1.13.1

git -C ~/om-work/om-temp-real-1.13.1 switch -c custom/om-1.13.1 --track origin/custom/om-1.13.1

산출물 — 로컬 custom/om-1.13.1 branch와 실제 커스터마이징 코드. 4장의 검증과 다음 단계의 등록자료 작성에 사용됩니다.

4. 결과 검증

판정 원칙 — 각 명령을 개별적으로 실행합니다. 예상 결과와 하나라도 다르면 등록자료 작성으로 이동하지 않습니다.
4-1. 현재 branch
git -C ~/om-work/om-temp-real-1.13.1 branch --show-current

예상 결과 — custom/om-1.13.1

4-2. official·custom commit
git -C ~/om-work/om-temp-real-1.13.1 rev-parse official/om-1.13.1

예상 결과 — e6199070c35f717f7ced512bb7b435b9d46b33a3

git -C ~/om-work/om-temp-real-1.13.1 rev-parse custom/om-1.13.1

예상 결과 — 59dae915342eaa3bdca1f9571bfa2ba4533c9a6f

4-3. 작업 폴더 변경 여부
git -C ~/om-work/om-temp-real-1.13.1 status --short

예상 결과 — 빈 출력. 사전 준비 단계의 13,853개 D도 사라져야 합니다.

4-4. 실제 커스터마이징 원본 동일성

수행 내용 — custom branch와 kb-source/main의 파일 내용을 비교합니다.

git -C ~/om-work/om-temp-real-1.13.1 diff --quiet custom/om-1.13.1 kb-source/main
echo $?

예상 결과 — 0. 두 코드의 파일 내용이 같다는 뜻입니다. 1이면 중단합니다.

4-5. 커스터마이징 변경 파일 수

수행 내용 — official과 custom 사이에서 달라진 파일 수를 확인합니다.

git -C ~/om-work/om-temp-real-1.13.1 diff --name-only official/om-1.13.1 custom/om-1.13.1 | wc -l

예상 결과 — 113. 이는 변경 파일 수이며 BANK-OM 커스터마이징 ID 수가 아닙니다.

4-6. official 기준 포함 여부

수행 내용 — custom branch의 Git 이력에 official 기준 commit이 포함되어 있는지 확인합니다.

git -C ~/om-work/om-temp-real-1.13.1 merge-base --is-ancestor official/om-1.13.1 custom/om-1.13.1
echo $?

예상 결과 — 0. custom이 공식 1.13.1을 기준으로 이어진 코드라는 뜻입니다. 1이면 중단합니다.

5. 완료 기준

  • 현재 branch가 custom/om-1.13.1입니다.
  • 로컬 official commit이 e6199070…입니다.
  • 로컬 custom commit이 59dae915…입니다.
  • git status --short가 빈 출력입니다.
  • 실제 원본 동일성 결과가 0입니다.
  • 변경 파일 수가 113입니다.
  • official 기준 포함 여부 결과가 0입니다.

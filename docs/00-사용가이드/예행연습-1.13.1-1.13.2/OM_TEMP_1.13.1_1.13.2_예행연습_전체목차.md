# OM_TEMP 1.13.1 → 1.13.2 예행연습 전체 목차

> 문서 성격: 예행연습 가이드를 실행 순서대로 여는 시작 페이지입니다. 1단계부터 순서대로 진행하며, 각 페이지의 완료 기준을 충족한 뒤 다음 페이지로 이동합니다.
> 순서 원칙: 기준 코드 준비 → BANK-OM ID와 코드 연결 → 등록자료 승인 → 공식 버전 영향 확인 → 코드 병합 → 최종 검사 → 릴리즈 후보 고정.

## 1. 전체 진행 흐름

```text
1. 로컬 준비
   ↓
2. official·custom branch 확인
   ↓
3. 변경 파일을 BANK-OM ID에 연결
   ↓
4. BANK-OM ID별 commit 후보 구성
   ↓
5. 코드 정리와 등록자료 초안 준비
   ↓
6. 사용할 검사기와 판정 방식 학습
   ↓
7. 1.13.1 등록 승인·apply·기준 검사
   ↓
8. 공식 1.13.2 준비·병합 전 영향 검사
   ↓
9. vendor merge·충돌 해결
   ↓
10. 1.13.2 최종 검사·승인
   ↓
11. 검증 tag·release branch 생성
```

> **\*참고 — official branch**는 해당 버전의 공식 OpenMetadata 코드만 담는 branch입니다. **custom branch**는 공식 코드에 BANK-OM 변경이 적용된 작업 branch입니다. **release branch**는 검사와 승인을 통과한 정확한 custom commit을 운영 후보로 고정한 branch입니다.

## 3. 순서를 건너뛰지 않는 이유

- 3단계의 파일–ID 관계가 없으면 4~7단계에서 어느 BANK-OM ID를 검사해야 하는지 확정할 수 없습니다.
- 7단계의 1.13.1 기준 검사 없이 8단계로 이동하면 업그레이드 전 상태와 업그레이드 후 상태를 비교할 기준이 없습니다.
- 8단계의 영향 검사를 병합 뒤에 실행하면 새 공식 코드가 건드린 경로를 사전에 검토한다는 목적이 사라집니다.
- 9단계에서 candidate SHA가 확정되기 전에 10단계 검사를 실행하면 검사한 코드와 릴리즈할 코드가 달라질 수 있습니다.
- 10단계의 필수 결과와 승인이 없으면 11단계의 tag·release branch를 만들지 않습니다.

## 4. 현재 중단 조건

- 공식 OpenMetadata `1.13.2` tag·commit이 확인되지 않으면 8단계에서 중단합니다.
- 등록 변경안이 사용자 승인을 받지 못하면 7단계의 `apply`를 실행하지 않습니다.
- 검사 결과에 `BLOCK` 또는 `ANALYSIS_ERROR`가 있으면 11단계로 이동하지 않습니다.
- T91을 실행할 승인된 운영 경로와 유효한 release lock이 없으면 tag·release branch 생성 전에 중단합니다.

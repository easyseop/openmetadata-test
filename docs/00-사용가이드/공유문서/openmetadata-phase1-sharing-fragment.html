01

우리의 목적

자체 제품을 새로 만드는 것이 아니라, 공식 OpenMetadata를 안전하게 계속 사용하는 것이 목적입니다.

유지할 것 공식 OpenMetadata

공식 기능과 보안 업데이트를 계속 반영합니다.

보호할 것 등록된 행내 기능

각 기능을 BANK-OM ID별 독립 변경 기록으로 관리합니다.

증명할 것 병합 후 생존과 실제 동작

공식 버전 병합 뒤 BANK-OM 코드가 남았는지와 행내 환경 동작을 서로 다른 검사로 확인합니다.

현재 업그레이드·검사를 진행하는 코드 저장소 easyseop/OM_TEMP

공식 1.13.0과 BANK-OM-001~007을 바탕으로 1.13.1 검사 대상 코드를 만들고, 충돌·해결·검사를 연습합니다. 현재 결과는 BANK-OM 변경을 하나씩 적용해 충돌 위치를 확인한 연습 결과입니다. 아래에 설명하는 정식 병합 절차 전체를 완료했다는 뜻은 아닙니다.

검사 기준과 결과를 관리하는 저장소 easyseop/openmetadata-test

직원용 OpenMetadata 화면이 아니라, 각 BANK-OM의 변경 파일과 검사 기준을 기록한 Manifest, 검사기, 검사 결과, 가이드와 인수인계 문서를 관리합니다.

02

브랜치 전략

정식 운영에서는 직전 행내 코드에 새 공식 버전을 병합하는 방식을 사용합니다. 이 방식을 이 문서와 설정 파일에서는 vendor-merge라고 부릅니다.

fork/om-<version> OpenMetadata 포크 브랜치에는 행내 변경이 없는 공식 코드만 보관하고, custom/om-<version> 커스텀 브랜치에는 공식 코드와 BANK-OM 변경을 함께 보관합니다. 검증과 운영 승인이 끝나면 release/om-<version> 릴리즈 브랜치를 같은 commit으로 갱신하고 실제 운영 배포에 사용합니다. BANK-OM ID와 Manifest 작성 방법은 3번 · 검사 전 사전환경 설정에서 설명합니다.

공식 버전과 OpenMetadata 포크 브랜치 · 공식 코드만 유지 BANK-OM 변경과 커스텀 브랜치 · 행내 변경 적용

그림에서 무엇과 무엇이 합쳐지나? 새 공식 코드만 담은 OpenMetadata 포크 브랜치와, 직전 공식 코드에 BANK-OM 변경을 적용한 커스텀 브랜치가 합쳐집니다. 결과는 새 공식 버전과 행내 기능이 함께 들어 있는 다음 버전의 커스텀 브랜치입니다.

왜 T42를 병합 전에 실행하나? 새 공식 버전이 Manifest의 watch 경로를 바꿨는지 먼저 찾아, 영향을 받을 BANK-OM ID와 검토할 파일을 병합 전에 알기 위해서입니다. 결과가 APPROVAL이면 담당자가 영향 내용을 확인합니다. 새 공식 버전과 최종 커스텀 브랜치가 확정된 뒤 준비도구의 plan → 담당자 승인 → apply로 필요한 Manifest와 파생 등록자료를 갱신합니다. T42가 Git 충돌을 해결하거나 등록자료를 직접 수정하는 것은 아닙니다.

Git 충돌은 어디서 발생하나? 양쪽 코드가 같은 부분을 서로 다르게 수정했을 때 ③ 병합 단계에서 발생합니다. 담당자가 어느 내용을 유지할지 확인해 다음 custom branch에서 수정하고, 그 해결 내용을 Git 변경 기록으로 남깁니다.

충돌 해결 때 새 BANK-OM을 만드는가? 기존 기능을 새 공식 버전에 맞춘 것이라면 같은 BANK-OM ID를 사용합니다. 기존 Manifest를 새 버전 등록 묶음으로 복사해 다시 검토하고, 해결 과정에서 변경 범위나 검증 기준이 달라진 항목만 갱신합니다. 별도 업무 기능이 생겼을 때만 새 ID와 Manifest를 만듭니다.

검사 BLOCK은 무엇이 다른가? Git 병합은 끝났지만 Manifest 범위, 필수 구현, 테스트 또는 승인 조건을 통과하지 못한 경우입니다. 이때도 다음 custom branch를 보완하지만 Git 병합 충돌과는 다른 문제입니다.

검사를 통과하면 바로 배포하는가? 아닙니다. 먼저 검사에 통과한 정확한 코드에 검증 완료 태그를 붙입니다. 전체 빌드, 행내 API·화면·DB 테스트, Release lock, 담당자 승인과 실제 배포 파일 일치를 확인한 뒤 릴리즈 브랜치가 같은 commit을 가리키게 합니다. 실제 운영 배포는 이 릴리즈 브랜치를 사용합니다.

현재 OM_TEMP 연습은 이 그림과 완전히 같은가? 아닙니다. 현재는 어느 BANK-OM에서 충돌하는지 확인하기 위해 변경 기록을 하나씩 적용했습니다. 따라서 BANK-OM별 충돌 진단 결과는 있지만, 위 정식 병합 절차 전체를 검증한 결과는 아닙니다.

## 3. 검토 질문

### 설계 타당성

1. **A2 가산 전용 불변식** — "우리 변경은 공식 대비 순수 추가"라는 불변식이
   실제로 성립하는가? 정당한 삭제(공식이 흡수한 커스텀 제거, 폐기된 API 정리)를
   어떤 경로로 허용해야 규칙이 무력화되지 않는가? 현재 −52줄이 전부 안전한가?
2. **A4 이동/유실 판정** — fragment 전역 검색의 오탐·미탐 조건은 무엇인가?
   짧은 fragment의 우연 일치, 동일 fragment 복수 존재, 주석·테스트 내 존재,
   공백·포맷 변경을 어떻게 다뤄야 하는가?
3. **A6 심볼 시그니처 대조** — Java와 TypeScript에서 실현 가능한 **최소** 형태는
   무엇인가? 전체 AST 없이 "우리가 참조하는 공식 선언의 변경"만 잡는 방법이 있는가?
4. **A14 독립 이중 해소** — 두 세션이 **같은 방식으로 틀릴** 상관성을 어떻게
   낮추는가? 일치가 정답을 의미하지 않는 실패 모드를 열거해 달라.
5. **A15 컴파일러 강제** — 현재 커스텀에서 누락 시 컴파일이 깨지는 지점이
   실제로 몇 곳인가? `EntityTypeName: Record<EntityType, string>` 외에 무엇이 있는가?

# 4. 오늘 확정된 판단

## 4-1. 검사기를 앞세우지 않는다

"편리함 vs 안전함"으로 붙으면 편리한 쪽이 이긴다. 특히 세 번 성공한 실적이 있으면
그렇다. **PPT 운영 방식 보완으로 접근한다.**

프레이밍도 중요하다.

```
❌ "방향을 LLM 상호작용으로 바꿨습니다"    → 이전이 틀렸다는 뜻, 낭비 소리가 나옴
✅ "각자 하다 보니 서로 필요한 걸 갖고 있더라"
```

두 번째가 사실이기도 하다. 실제로 두 갈래가 각자 진행됐고 이제 합치는 것이다.

## 4-2. 검사기의 진짜 상품은 이 한 줄이다

> **"LLM이 잘한다" → "LLM이 틀려도 걸린다"**

리더는 "LLM이 잘한다"를 검증할 수 없다. 믿는 수밖에 없어서 승인이 안 난다.
"틀려도 걸린다"는 메커니즘을 보여주면 검증할 수 있다.

## 4-3. 유사도 검색은 제거한다

**옮긴 주체가 어디로 옮겼는지 안다.** 병합하고 재이식한 게 LLM인데 기계가 다시
추측할 이유가 없다.

```
LLM 이 신고 → 기계가 그 경로에서 검산(3초) → 테스트로 확인 → 사람 승인
```

추측 두 개가 추측 하나보다 낫지 않다. 여기 붙어 있던 P0 2건도 함께 사라진다.

신고를 안 하면 조각 대조가 BLOCK 되어 진행이 막힌다. **막히는 게 정상 동작이다.**
검색으로 대신 찾아주면 오히려 기록을 안 남길 유인이 생긴다.

## 4-4. ID는 `BANK-OM-*`로 통일한다

정본은 `harness/registrations/om-temp-1.13.1/customization-registry.yaml`.
Contract·Manifest·조각 790개가 이미 이 ID에 묶여 있다. 새 번호를 만들면 매핑표가
하나 더 생기고 그게 다시 틀어진다.

**PPT 3~4장의 `ReportProject`는 현재 `QueryReport`(BANK-OM-002)다.**
커스텀 HEAD `8ac18ad0`에 `ReportProject` 경로가 없고 `QueryReport`만 있다.

| ID | 기능 |
|---|---|
| BANK-OM-001 | 기준코드(InstanceCode) |
| BANK-OM-002 | 쿼리 리포트(QueryReport) |
| BANK-OM-003 | 데이터 검증 결과(Data Assertions) |

## 4-5. 검사기 P0는 4건만 하고 종료한다

`policy_guard` 연결은 2차로 미룬다. 근거는 세 가지다.

1. 제품 Candidate는 정책 파일에 **물리적으로 접근 불가**. 저장소가 다르다.
2. 검사기 저장소 변경은 현재 커밋마다 Claude 검토를 거친다. **사람 검토가 대체 중.**
3. 올바른 수정은 단순 연결이 아니라 **판정 대상 재정의**다. 정책 glob이 검사기
   저장소를 기술하는데 판정 대상은 제품 저장소라, 순진하게 연결하면 영구 `PASS`를
   내는 안전 연극이 된다.

대신 문서에 상태를 명시한다.

```
T70 policy-self-protection: 구현됨 · 미연결 · 사람 검토로 대체 중
```

# 5. 검사기의 실체

## 5-1. 하는 일 8가지

1. **우리가 뭘 고쳤는지 읽는다** — BANK-OM 7개, 경로 112개, 조각 790개
2. **검사할 코드를 하나로 못 박는다** — 나중에 바꿔치기하면 걸림
3. **Git에서 사실을 캔다** — 누가 뭘 바꿨나·지웠나·옮겼나
4. **병합 전 위험 4가지** — 의존 공식 파일 변경 / 규칙 파일 변경 / 설정 구조 변경 / 감시 경로 추천
5. **병합 후 확인 7가지** — 양쪽 계보 / 민감 영역 / 부채 / 등록 범위 / 등록 서류 / 소스 생존 / 기능 테스트
6. **조각 790개 대조** — 3초
7. **테스트 결과 해석** — 건너뛴 것을 통과로 치지 않음
8. **결과에 지문** — 나중에 고치면 들킴

## 5-2. 안 쓰는 일 7가지

| 하는 일 | 왜 안 쓰나 |
|---|---|
| 배포 승인 절차 | 아직 운영 배포를 안 함 |
| 급할 때 예외로 통과 | 예외 규칙 미정 |
| 인터넷 없는 망에서 검사 | 해당 환경 아님 |
| 커스터마이징 폐기 처리 | 뺄 기능 없음 |
| 작은 변경 빠른 통과 | 필요 없음 |
| **규칙을 몰래 못 바꾸게 막기** | **만들어놓고 안 붙였음** |
| 충돌 처리 (같은 게 두 벌) | 하나는 죽은 코드 |

앞의 다섯은 운영에 들어가면 필요하다.

# 6. 조각 790개 — 정체와 한계

## 6-1. 무엇인가

> **"이 파일 이 자리에 이 내용이 있어야 한다"를 미리 적어둔 목록.**

```
790개 중
  737개  다국어 번역 키 (20개 언어)
   53개  실제 코드 조각 (Java·TS·SQL)
```

실물 예시:

```
{"pointer": "/label/instance-code", "expected": "인스턴스 코드"}
public static final String INSTANCE_CODE = "instanceCode";
```

1.13.1 코드에서 자동 추출해 사람이 승인한 것이다. 그래서 **"1.13.1에서 잘 돌던
상태의 스냅샷"**이고 정답지 역할을 한다.

## 6-2. PPT의 MD와 무엇이 다른가

```
일지    작업하면서 "이렇게 했다"고 적는 것        ← KB-CUSTOM-NEW/MODIFIED
정답지  작업 전에 "이게 있어야 한다"고 정해둔 것   ← 조각 790개
```

일지는 작업한 사람이 작업 후에 쓴다. 작업이 틀렸으면 일지도 같이 틀린다.
**틀린 걸 틀린 대로 적어놓은 문서로는 틀렸다는 걸 알 수 없다.**

| 조건 | KB-CUSTOM-* | 조각 790개 |
|---|---|---|
| 작업 전에 정해져 있나 | ✗ | ⭕ |
| 기계가 맞춰볼 수 있나 | ✗ | ⭕ 3초 |
| 작업자가 못 고치나 | ✗ | ⭕ 다른 저장소 + 지문 |

## 6-3. 매칭 방식과 한계

```
1. 공백·줄바꿈·주석을 전부 지운다
2. 토큰으로 쪼갠다
3. 우리 조각의 토큰이 파일 안에 연속으로 붙어 있는지 본다
```

| 상황 | 결과 |
|---|---|
| 두 기능 코드 순서가 바뀜 | 괜찮음 (각 조각을 따로 찾음) |
| 조각 위아래에 공식 코드 추가 | 괜찮음 |
| 들여쓰기·줄바꿈·주석 변경 | 괜찮음 |
| 조각 **한가운데**에 공식 코드가 끼어듦 | 깨짐 → 사람이 확인 |
| 값이 바뀜 (`sybaseConnection` → `officialConnection`) | 잡음 |
| **있는데 안 돎 (죽은 코드)** | **못 잡음 ← 진짜 약점** |
| 우연히 같은 토큰 열이 다른 곳에 있음 | 개수 불일치로 오탐 |

# 7. 파일이 이동하면

## 7-1. 검증은 테스트뿐이다

| | 파일 이동 시 |
|---|---|
| 조각 대조 790개 | **무조건 깨짐** — 경로에 묶여 있음 |
| 이동 후보 탐색 | "저기로 간 것 같다"까지만 |
| **테스트** | **안 깨짐** — 경로를 모르고 기능만 봄 |

```
1. 조각 대조 BLOCK  → "여기 뭔가 바뀌었다" 알람
2. 사람/LLM 이 새 위치 확인·재이식·신고
3. 테스트로 기능 확인            ← 여기가 진짜 검증
4. 정의를 새 경로로 이관          → 다음번을 위한 정비
```

**3번만 검증이고 1·2·4는 정비다.**

## 7-2. 1.13.2 실제 사례

```
EntityUtils.tsx  공식이 삭제
  → EntityLinkUtils.ts            getEntityLinkFromType
  → EntityBreadcrumbPureUtils.ts  getEntityBreadcrumbs
  → EntityNameUtils.ts            EntityTypeName

EntityUtils.test.tsx  파일명 그대로 남고 import 만 새 위치로 바뀜 → 테스트 계속 돎
새로 쪼개진 3개 파일   자기 테스트 없음
```

**이번엔 운이 좋았다.** 공식이 테스트 파일을 안 지웠고 barrel 구조라 import만 고치면
됐다. 다음번에 테스트 파일까지 쪼개지면 **아무도 모르게 검증이 없어진다.**

## 7-3. 그래서 필요한 것

**"이 기능에는 이 테스트가 있어야 한다"도 등록해야 한다.**

```
지금 등록됨   BANK-OM-001 → 코드 조각 32개
빠짐         BANK-OM-001 → 필수 Jest 테스트 목록
```

Contract에 `required_tests`가 있지만 **런타임 9개뿐**이다. Jest 88개는 어디에도
등록돼 있지 않아, 사라져도 검사기가 모른다.

## 2. 지금 수정하는 4건이 기여하는 것

네 건의 공통 성격은 하나다.

> **판정에 쓰인 입력이나 근거가 바뀌었는데 증거에 남지 않는다.**

이것은 악의적 공격 방어가 아니라 **정상 작업 중에 조용히 일어나는 변경을 눈에
띄게 만드는 일**이다. 공식이 구조를 바꾸면 Contract test도 정당하게 고쳐야 하고,
그때 그 사실이 기록돼야 한다.

| P0 | 지금 상태 | 수정 후 |
|---|---|---|
| A | `sensitive-zones.yaml` 완화 → T41 결과 변화, digest 불변 | digest 변경 → 재승인 필요 |
| B | `test_sybase.py` 본문 교체 → digest 불변 | digest 변경 → `APPROVAL` 정지 |
| C·D | `symbol_overlap` 후보 1건 → `BLOCK`이 `APPROVAL`로 | 후보 유무와 무관하게 `BLOCK` 유지 |
| E | 무관한 PASS 증거로 이관 승인 가능 | BANK-OM ID·정의·경로 결속 필수 |

A와 B는 digest 목록에 항목을 추가하는 일이며 설계 논의가 필요 없다.
D는 안 B(후보 검색 유지 · 판정 영향 제거)를 따른다. B와 E는 "증거를 BANK-OM·정의에
묶는다"는 같은 원리이므로 한 설계로 처리한다.

## 3. F(`policy_guard` T70)를 2차로 미루는 근거

검토 결과 자체는 유효하다. 다만 **지금 규모에서 실질 기여가 작다.**

1. 제품 Candidate는 정책 파일에 **물리적으로 접근할 수 없다.** 정책은 검사기
   저장소, Candidate는 제품 저장소다. 실측으로 `harness/**`, `policies/**`,
   `.bank/**`, `docs/02-설계/**`, `STATUS.md`가 제품 저장소에 없음을 확인했다.
2. 실제 위험은 검사기 저장소의 자기수정인데, 현재 그 저장소의 모든 commit이
   Claude 검토를 거치고 있다. **사람 리뷰가 이미 같은 역할을 수행 중이다.**
3. 올바른 수정은 단순 연결이 아니라 **판정 대상의 재정의**다. 정책 glob이 검사기
   저장소를 기술하는데 판정 대상은 제품 저장소이므로, 순진하게 연결하면 영구
   `PASS`를 내는 안전 연극이 된다. 별도 설계가 필요하다.

### 대신 지금 해야 할 것

**문서에 상태를 명시한다.** 구현된 안전장치가 실제로는 연결돼 있지 않다는 사실
자체가 위험이며, 그것은 문서 한 줄로 해소된다.

```text
T70 policy-self-protection: 구현됨 · 미연결 · 사람 검토로 대체 중
사유: 정책과 Candidate가 서로 다른 저장소에 있어 현행 glob이 적용되지 않음
해소 조건: 검사기 저장소 변경을 대상으로 하는 재설계 후 양 phase 연결
```

F가 필요해지는 시점은 팀이 여럿이 되거나 사람 검토 없이 자동으로 도는 파이프라인이
생길 때다.

## 4. 착수 순서

의존 관계를 반영한 순서다.

```text
1. A  registration digest 목록 확장          (가장 작음, 다른 수정의 전제)
2. B  test 구현 digest 결속                  (E 와 한 설계)
3. C  오탐 고정 test 2건 해제                (D 가 회귀로 잡히게 하려면 선행)
4. D  유사도 후보 판정 분리 (안 B)
5. E  기능 test 증거 결속                    (B 와 한 설계)
6. F  문서에 "미연결·사람 검토 대체" 명시     (구현 아님)
```

각 단계마다 먼저 실패해야 할 반례 test를 추가하고 전체 harness 회귀를 실행한다.
회귀 test 목록은 두 검토 결과 문서의 해당 절을 사용한다.

## 5. 이 수정이 목표를 진전시키는가

정직하게 구분한다.

**진전시키지 않는다.** 이 여섯 건은 이미 만든 것이 무너지지 않게 붙잡는 일이다.
새 검증 능력을 더하지 않는다.

**목표를 실제로 진전시키는 것은 다음 둘이다.**

```text
1.13.2 Candidate 로 Runtime Contract 실행   ← BANK 기능이 실제로 도는지
T61 patch-kill 5/5                          ← Contract 가 실제로 검증하는지 (현재 2/5)
```

이 둘이 되기 전까지 검사기는 **"소스에 코드가 있다"까지만** 말할 수 있다.
1.13.1 Runtime Contract는 이미 9/9 통과했고, 미완료 대상은 1.13.2 Candidate다.
